# Contract - forkdrift

This contract is the executable spec for forkdrift. Every obligation below is stated so it can fail. The full contract is the first build act of this repo and it extends the stub obligations written here.

## Stub obligations

FD-S1. Two runs that define the same interface in incompatible ways raise an alarm, and an alarm that does not quote both conflicting definitions is a defect the tests must catch.

FD-S2. Two runs whose definitions of a shared interface agree raise no alarm, and a false alarm on agreeing runs is a defect the tests must catch.

FD-S3. Every alarm names the concept that diverged and the runs that diverged on it, and an alarm missing either is rejected rather than reported incomplete.

FD-S4. Forkdrift detects and reports only, and it never edits a run, a branch, or a definition in order to reconcile a divergence it found.

FD-S5. Every fixture and example in this repo is synthetic and built for this repo, and no real trace or session data appears anywhere in the tree.

## Round 1 obligations

Round 1 defines the artifact format in this contract and builds the reader and the comparison over it. The format is forkdrift's own, so no outside tool behaviour needs probing before the obligations can rest on it. An artifact is a recorded text that one run left behind for one interface, and the comparison runs on two recorded artifacts only and never on a live run.

The format in brief is shown here once, and the obligations below state it as rules that can fail.

```
interface shard-store

replicas = 3
timeout = 30
operation fetch = record
label primary = node-a
excludes = legacy-mode
```

A meaningful line is a line that is neither blank nor a comment, and a comment line is a line whose first character that is not a space is the hash character. The first meaningful line names the interface. Every later meaningful line is a term line, an operation line, a label line, or an excludes line. A term line is a term name, an equals sign, and a value. An operation line is the word operation, an operation name, an equals sign, and a result type. A label line is the word label, a label name, an equals sign, and a value. An excludes line is the word excludes, an equals sign, and a comma separated list of names, and an artifact carries at most one excludes line. Term names, operation names, label names, and interface names are identifiers that start with a letter or an underscore and continue with letters, digits, underscores, dashes, or dots.

FD-1. An artifact parses only when its first meaningful line names exactly one interface and every later meaningful line matches one of the statement forms this contract defines, and a text that breaks that shape is not an artifact and is never compared.

FD-2. A malformed artifact is refused with an error that names the source and the defect, and the refusal covers a missing interface line, a meaningful line that matches no statement form, a duplicate term name or operation name or label name, an empty value, and an artifact that defines a name its own excludes line forbids, and no refusal ever surfaces as a traceback or as a partial report.

FD-3. When both artifacts state the same term and the two values differ after the normalizations named in FD-6, the comparison raises exactly one divergence for that term, and the report quotes the term line from each artifact verbatim and names the source each line came from.

FD-4. When both artifacts state the same operation and the two result types differ after the normalizations named in FD-6, the comparison raises exactly one divergence for that operation, and the report quotes the operation line from each artifact verbatim and names the source each line came from.

FD-5. When one artifact excludes a name and the other artifact defines that name as a term or as an operation, the comparison raises exactly one divergence for that name, and the report quotes the excludes line and the defining line verbatim and names the source each line came from.

FD-6. The only normalizations are the ones named here, namely leading and trailing whitespace is stripped from every line, runs of whitespace inside a value collapse to a single space, and a value that reads as a finite number on both sides compares by numeric worth rather than by its characters, and statement order never matters, and a difference that one of these normalizations removes raises no divergence.

FD-7. Label lines are local annotations that this format declares non-semantic, and a label that is renamed or revalued between the two artifacts raises no divergence, and label names are never dereferenced inside term values or operation result types in this round.

FD-8. A term or an operation stated in only one of the two artifacts raises no divergence in this round unless the other artifact excludes that name, and this limit is a stated limit of the round and is recorded here so a later round can retire it on purpose.

FD-9. Two artifacts that name different interfaces are refused with an error that names both interface names, because the comparison is defined only over two artifacts that describe one and the same interface.

FD-10. The report lists divergences sorted first by interface name and then by the name that diverged and then by divergence kind, and running the comparison twice over the same pair of artifacts produces byte identical reports.

FD-11. The command line tool exits with code 0 when the pair agrees, with code 1 when at least one divergence is found, and with code 2 when either artifact is malformed or the two artifacts name different interfaces or an input file cannot be read, and a refusal prints one error line to the error stream and never a traceback.

FD-12. The exactly one divergence that FD-5 promises holds per excluded name and per direction, and when the other artifact defines the excluded name both as a term and as an operation, the single divergence quotes the excludes line and both defining lines, each with its source named.

FD-13. The lines the report quotes under FD-3, FD-4, and FD-5 are the statement lines after the leading and trailing whitespace strip named in FD-6 has been applied, and the word verbatim in those obligations is read subject to that strip, with all internal spacing preserved exactly.

FD-14. The self-exclusion refusal in FD-2 covers names defined as terms or as operations, and a name carried only as a label is not a definition for that refusal, because FD-7 declares labels non-semantic.

## Round 2 obligations

Round 2 retires the presence limit that FD-8 stated for Round 1 and recorded for a later round to retire on purpose. The comparison now reports the names only one of the two artifacts defines, and the obligations below state the new kind, its interplay with the exclusion rules, and its place in the report order. No other Round 1 obligation changes.

FD-15. The limit stated in FD-8 is retired. A term statement or an operation statement that one artifact makes and the other artifact does not make in the same form is a one-sided statement, and the one-sided statements for one name together raise exactly one divergence of a fourth kind named presence for that name. The report block for a presence divergence follows the row grammar of the blocks Round 1 defined, one left row and one right row and the further row of FD-12 when a side makes one-sided statements in both forms. Each side quotes the one-sided statement lines it makes, the first in its side row and the second in the further row, taken term first and operation second as FD-12 takes defining lines. A side that makes no one-sided statement for the name quotes its interface line on its side of the block, so every row of the block quotes a line the named source states. A name that both artifacts state in the same form raises no presence divergence for that form, and when the values in that form differ after the normalizations of FD-6 the divergence of FD-3 or FD-4 is the one raised for that form. The kind presence is a new value in the block header and no new row shape is introduced, so a reader of the Round 1 report format meets a kind value it can name in a grammar it already parses.

FD-16. The presence kind and the exclusion contradiction never both fire for one name. When one artifact excludes a name and the other artifact defines that name, the only divergence raised for that name is the exclusion contradiction of FD-5 as FD-12 amends it, and no presence divergence is raised for that name in either direction. A name that one artifact excludes and neither artifact defines raises no divergence, and a name that both artifacts exclude raises no divergence. Labels raise no presence divergence, because FD-7 declares label lines non-semantic. The self-exclusion refusal of FD-2 as FD-14 reads it is unchanged, and an artifact that defines a name its own excludes line forbids is refused and never compared.

FD-17. The presence kind stands in the ordering of FD-10 on the same terms as the kinds Round 1 defined, so the report lists divergences sorted first by interface name and then by the name that diverged and then by divergence kind, with a presence divergence placed by its interface, its name, and its kind. The exit codes of FD-11 are unchanged, and a presence divergence counts as a divergence under that rule, so a pair whose only divergences are presence divergences exits with code 1 and a pair with no divergence of any kind exits with code 0.

FD-18. Amendment, added by the Round 2 review. Two corrections. First, the further row a block carries when one side defines a name both ways is labelled for the side its line comes from, left or right as the case may be, in exclusion blocks as in presence blocks; the rendering before this amendment labelled every further row right, which contradicted the source it named whenever the left side defined the name both ways, and the Round 1 reports whose further rows come from the right side are unchanged byte for byte. Second, FD-15's reader sentence is restated to the strength the evidence supports: the presence kind changes no row's shape, and a report carrying it is written in the grammar Round 1 defined, but a reader that admits only the Round 1 kind values must still be taught the new value before it can read such a report, and teaching crosscurrent's parser is that repo's own round's work.

## Round 3 obligations

Round 3 states the grammar of a number, which FD-6 named by worth without ever stating which values read as numbers, so the question fell to the string parser of the implementation and a Python source literal convention stood inside recorded data unnamed. The amendment below states the grammar as a grammar of this format, and records two readings the earlier rounds left unnamed. No other obligation changes. The behaviour that changes is the two cases the amendment names, the underscore case and the digit characters of other scripts.

FD-19. Amendment, added in Round 3. A number in this format is an optional sign, then one or more digits with an optional fraction, or a fraction standing alone, then an optional exponent. A fraction is a point followed by zero or more digits when digits stand before the point, so 5. reads as the number five, and a point followed by one or more digits when no digits stand before it, so .5 reads as the number five tenths. An exponent is the letter e or E, an optional sign, and one or more digits. An underscore never stands inside a number, and the spellings of infinity and of not a number are never numbers. The digits of this grammar are the ASCII digits 0 to 9, and a digit character from another script is not a digit of this format, so such a value compares by its characters where the implementation's parser once read it as a number. Two values that both match this grammar compare by exact decimal worth under FD-6, so integers of any length compare exactly and decimal fractions compare digit for digit past the point. The worth comparison is carried out on the number's own digits and exponent, so it is exact at any exponent the grammar admits, and two spellings of one number agree however large the exponent stands. A value that does not match this grammar compares by its normalized characters under FD-6, so 1_000 against 1000 raises the term value divergence of FD-3 where the two agreed before this amendment, and 1_000 against 1_000 still agrees. Two readings stand recorded here as readings and not as new behaviour. A name repeated inside one excludes list is inert, because the list is a set of names and a repetition adds nothing to it. The refusals for a second excludes line, an empty excludes list, a trailing comma in an excludes list, and a repeated interface line stand exactly as FD-1 and FD-2 already produce them.

## Round 4 obligations

Round 4 gives forkdrift the sweep. The comparison of Rounds 1 to 3 runs on exactly two recorded artifacts, and a fleet of runs leaves more than two tapes behind, so the sweep compares one baseline artifact against each of several others in turn and prints one document that attributes every divergence to the pair that raised it. The pairwise comparison itself does not change, and the sweep document is a new document kind that stands beside the pairwise report and never replaces it.

FD-20. A sweep compares one baseline artifact against each of several other artifacts in turn, in the order the others are given, and every comparison in a sweep is exactly the pairwise comparison of FD-3 to FD-19 over the same two artifacts, with the same parser, the same divergences, and the interface refusal of FD-9 applied pair by pair. The library entry point sweep_artifacts takes the baseline and the others and returns one divergence list per other artifact, in the order the others were given, and a pair that refuses refuses the whole sweep with the refusal that pair raises, so no partial result stands in for a sweep one of whose pairs could not be compared.

FD-21. The sweep document prints, for every pair in order, one header line and then that pair's report in the grammar of FD-3 to FD-19, and the report of a pair that agrees is empty, so an agreeing pair contributes its header line alone and a sweep in which every pair agrees prints exactly its header lines. The header line reads pair left, then the baseline source in parentheses, then right, then the other source in parentheses, in the form pair left (SOURCE) right (SOURCE) with the two source names standing where the capital words stand, and the line is built from the two source names and the fixed words pair and left and right alone. The header line stands outside the block grammar of the pairwise report, because a block opens with the word divergence and a row opens with two spaces and a side word, and the header opens with the word pair at the start of the line, so no reader of the pairwise grammar can take a header line for a block or for a row, and the sweep document is never a pairwise report and is never fed to a reader of pairwise reports.

FD-22. The command line gains a sweep form beside compare, and compare keeps its exact two argument shape and its behaviour in every byte. The sweep form takes one baseline argument and one or more other arguments, and a sweep asked for with no other artifact is a usage error that the argument parser reports on the error stream with exit code 2 before any file is read, and no document is printed. A sweep over files reads and parses the baseline before any pair is compared, and then takes the others in the order given. The sweep exits with code 0 when every pair agrees, with code 1 when at least one pair diverges, and with code 2 when any pair refuses, and a refusal in any pair refuses the whole sweep in the discipline of FD-11 and FD-2, one error line on the error stream naming the refusal that pair raises, no document and no partial document on the output stream, and never a traceback, and the refusal reported is the first refusal in pair order.

FD-23. The pairwise report grammar and the compare command are unchanged in every byte, and the committed pairwise example documents stand exactly as Rounds 1 to 3 left them. The committed examples gain one sweep document, produced by running the tool itself over the committed tapes with examples/run-a.tape as the baseline and examples/run-b.tape and examples/presence-a.tape and examples/presence-b.tape as the others in that order, and the document is pinned byte for byte the way the pairwise example documents are pinned.

## Round 5 obligations

Round 5 ports forkdrift from Python to a native Rust crate. The format, the comparison, the report grammar, and the sweep do not change, and the obligations below state the crate shape, the invariants in the crate's own form, and the print and argument disciplines the new runtime must reproduce. The readings the port rests on were probed against the Python implementation and its runtime before the build, and the probe corrections after the obligations record the places where the probes corrected the reading of an earlier obligation. Forkdrift still detects semantic divergence only, and nothing in this port performs a reconciliation.

FD-24. The tool is a native Rust crate. Its manifest declares the package forkdrift on edition 2024 with a library target and a binary target, clap 4 with the derive feature and thiserror 2 as its dependencies, anyhow 1 confined to the binary entry point, and sha2 and serde_json as development dependencies, sha2 for the setup tests and serde_json for the generated command line corpus alone. The shipped library and binary carry no serde dependency and read and write no JSON, because forkdrift's data is recorded text in the grammar of FD-1 and reports in the grammar of FD-2 and FD-21.

FD-25. Every obligation from FD-1 through FD-23 holds in the Rust implementation with unchanged meaning, and the Python test corpus is ported test for test into Rust tests under the tests directory that keep the corpus file names, so every behaviour the Python suite pinned stays pinned. Where an earlier obligation names the Python implementation, its test runner, or its module layout, the crate's own form of the same check stands in its place, and FD-26 states the setup invariants in the crate's own form.

FD-26. The setup invariants hold in the crate's own form. The canonical block of the agent instructions file keeps the digest it carries today, measured over the text above the repo annex heading, and the annex keeps naming this contract. The stub obligations of the first slice stand in this contract exactly as written. The readme keeps exactly one closed rounds count of the pinned form, and its status line keeps reporting the rounds this contract has closed. No tracked text file in the repo contains an em dash or an en dash, and the scan covers the extensionless records and the manifest files as well as the suffixed ones.

FD-27. The committed example documents stay the documents the tool itself produces, and the Rust binary regenerates the pairwise reports of FD-23 and the sweep document of FD-23 byte for byte, so the example tests that pin them keep passing against the port with no byte changing in any committed example file.

FD-28. The worth comparison of FD-6 and FD-19 is carried out on the number's own digit string and a signed exponent held at arbitrary precision, so it stays exact at any exponent the grammar admits, subject only to the conversion limit the probe correction to FD-19 records. The reader's text model is the oracle's own. Lines split on the oracle's boundary set with the carriage return and line feed pair counting as one boundary, and whitespace strips and collapses over the oracle's whitespace set, and both sets stand in the implementation as tables taken from the oracle runtime's own character data. The port carries discriminating pins for both tables, a behaviour pin for every boundary character and for the edges of every whitespace range, so deleting any entry from either table breaks a test.

FD-29. The implementation states its ceilings where the oracle has them and adds none of its own. The mantissa digit string is never converted to a number at any length, so integers of any length compare exactly, and a text of any size parses line by line with line numbers counted over the boundary set of FD-28. The one ceiling the oracle does hold, the exponent digit conversion limit, stands in the probe correction to FD-19, and the one divide the print discipline holds stands in FD-30.

FD-30. When the document cannot be printed because the reader of standard output is already gone, the command answers with status 120 and one line of its own on the error stream when the whole document is shorter than 8192 bytes, because the oracle's write stays buffered and the failure surfaces only at the exit flush, and with status 1 and one line of its own when the document runs to 8192 bytes or more, because the oracle's buffer empties inside the write and the failure escapes the command uncaught. Printed help follows the short case. A refusal line on the error stream is written plainly, and the status stands whether or not that write succeeds.

FD-31. The Python implementation, its tests, its project file, and its test configuration are removed in the same slice that lands the port, after the differential run against the Python implementation passes, and the tracked tree then holds no Python source. The continuous integration backstop runs the crate's test suite and nothing else.

FD-32. The command line keeps every functional outcome of FD-10, FD-11, and FD-22, meaning the exit statuses, the files read, and the contents of both streams. The argument presentation is the Rust argument parser's own, so help wording and malformed invocation wording follow the parser while no functional outcome follows it. The argument scan keeps the readings the probes established before the build, and the probe correction to FD-11 records them.

Probe correction to FD-2, recorded in the Round 5 contract pass before the build and governing where the two disagree. A report prints each source with the exact bytes the path was given in, so a path whose bytes are not valid UTF-8 stands in a report with those bytes unaltered, because the oracle decodes its arguments with the surrogate escape handler and encodes its report the same way. A refusal line names the same source with every undecodable byte written in the escaped form \udcXX, a backslash and the letters u and d and c and the byte's two lowercase hex digits standing where XX stands, because the oracle's error stream replaces what it cannot encode. The probe ran both shapes against a file whose name carries the byte 0xff and recorded the report line carrying the raw byte and the refusal line carrying the escaped form, and both shapes stand corrected here.

Probe correction to FD-10, recorded in the Round 5 contract pass before the build and governing where the two disagree. The name in the cannot read line is the oracle path library's folded form of the path as written and not the path as written itself. Empty components and single dot components fall away, dot dot components stay, a leading pair of slashes stays a pair while any longer run of leading slashes folds to one, and a path left with no components names a single dot, so an empty path argument reads as the current directory and fails with the directory wording against the name dot, and a directory named with a trailing slash fails against its folded name. Reports and parse refusals keep naming the path as written, and only the read refusal folds. The probe recorded the folded names for dotted, doubled, rooted, and empty paths against the oracle before the build.

Probe correction to FD-11, recorded in the Round 5 contract pass before the build and governing where the two disagree. The argument readings are the oracle parser's own and three of them are easy to get wrong. A separator token standing before any subcommand is itself read as the subcommand candidate, so it refuses as an invalid choice at status 2 and it blocks a help token after it the way any invalid candidate does, while inside a subcommand the separator hands the tokens after it to the command as values and a second separator token is itself a value. A token carrying a space is read as a path value whatever its prefix, and the help reading is taken before the space reading, so the token -h x asks for help while the token -- a.tape names a path. A token naming a negative number in the oracle's pattern is a path value, and the pattern reads a trailing newline as the end of the token, so -1 followed by a newline reads as the number while -1. and -1e3 do not read as numbers at all. A help token fires in any position up to the value that blocks it, and a help token written with an equals sign and a value refuses at status 2.

Probe correction to FD-19, recorded in the Round 5 contract pass before the build and governing where the two disagree. The exponent conversion refuses an exponent written with more than 4300 digits, and the refusal escapes the command uncaught at status 1 with nothing on the output stream, in a comparison and in a sweep alike, and the sweep prints no partial document. A zero mantissa rescues nothing, because the conversion runs before the zero check, and a value compared against its own exact text still agrees without any conversion taking place. The probe recorded the boundary at the oracle, 4300 digits converting and 4301 refusing, and the port answers the refusing shapes at status 1 with one line of its own on the error stream where the oracle prints a traceback.

Probe correction to FD-30, recorded in the Round 5 review pass after the build and governing where the two disagree. The closing sentence of FD-30 pictures the refusal status standing whether or not the error stream write succeeds, and that reading rested on probes of a dead standard output alone, because the pre-build probes never closed the error stream. Probed in the review pass with the reading end of the error stream closed before the command starts, the oracle answers 120 for a refusal and 120 for a usage error alike, because the line stays in the buffer and the failure surfaces at the exit flush, the same shape FD-30 records for a short document on a dead standard output. The port answers the same, so a refusal line or a parser error line that cannot be written to the error stream answers 120, and a line that lands keeps the status FD-11 and FD-32 already give it. The closing sentence of FD-30 stands corrected on this point.
